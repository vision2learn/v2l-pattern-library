**Chris:** Tools

As source code needs to be clean, consistent, and easy to maintain by existing developers, there are a number of tools that can be used in conjunction with the coding standards. 

For example, StyleLint finds and fixes problems in code; the tool identifies and reports when the code is not consistent with the coding standards. It is easy to configure as the style guide is added as the default coding standard and the team can also add their own rules if needed.

**Leah:** Code review

A code review which is also known as a peer review, is a form of software quality assurance. It is when one or more of the developer team would check each other’s source code in a given project.

Typical elements of a code review would be to include which standards would be used, first passes, using a ticketing system, run tests, check any changes made and then complete the review with an in-depth pass. 

Code reviews would speed up the process of the project as this would ensure consistency and that the standards are being met across the whole team.

**Chris:** Static analysis

Static analysis also known as Static Application Security Testing [SAST], is a tool that is used to automatically check code for weaknesses that may cause issues later on. It finds potential quality issues in the code before the program is run. 

It would be used to find and fix vulnerabilities, bugs, code errors, security risks, memory leaks, null pointers, buffer overflow, and any violations of the coding standard whilst the code is in a ‘static’ state [meaning whilst the code is not being run]. It is often used to comply with coding guidelines and industry standard. 

Typical elements of static analysis would involve, writing code, running a static code analyser, reviewing results, fixing any issues and then testing.
